# 記事一覧の継続読込の検証

2026-11-06。対象は `reader-stable-continuation` のローカル作業ツリー。移行元の読書仕様との対応は [OpenSpec提案](../openspec/changes/reader-stable-continuation/proposal.md) を参照する。実データや秘密は使用していない。

- Linux コンテナの Rust テスト43件に成功。合成データで、挿入・削除後の残存記事、公開日時の同率とタイムゾーン差、公開日不明、履歴順、期限切れ・改ざん、検索・タイムゾーン・フォルダー所属の変更、および従来offset APIを検証した。
- 画面のビルドと、Linux コンテナを使う読書・生産性・サイドバー・設定・アクセスのブラウザ回帰に成功。設定画面回帰には、IntersectionObserverなし、2ページ目の失敗とキーボード再試行、選択と履歴の保持、条件変更後の遅延失敗、および409時の明示的な一覧再読込を含む。
- 生成データのバックアップ、別volumeへの復元、再作成とworkerの停止を確認。OpenSpecの厳格検証は19項目成功。
- GitHub CIは確認していない。カーソル専用のPC・モバイル・全テーマ・全入力方式の組み合わせは網羅していない。

継続情報の署名鍵は単一Webプロセスのメモリ内にあり、再起動で無効になる。上限IDを超える新規記事は再読込まで表示しない。既存DBは削除した最大IDを再利用し得るため、再利用IDの新規記事を上限だけで必ず排除できるわけではない。記事の日時やフィルター対象が途中で変更された場合も履歴スナップショットにはならない。旧Webデータの完全変換・本番切替は対象外。
