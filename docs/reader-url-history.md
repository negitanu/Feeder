# Reader URL and history

The reader uses `view` (`all`, `unread`, `starred`, `recent`, `later`), `search`, `feed` or `folder`, `article`, `order`, `scope`, `any`, `exclude`, `published_from`, `published_to`, `feed_ids` and `include_muted` query parameters. IDs must be positive safe integers; text is limited to 500 characters; dates must be real ISO calendar dates. If both sources are given, feed wins. Invalid values are discarded. Unknown query parameters are retained. URL text can appear in browser history and shared links; avoid placing confidential searches in links.

The `later` view requests saved-for-later articles using `later=true`. `include_muted=true` includes muted articles; when omitted or set to any other value, muted articles remain hidden. Both settings are restored through browser history and retained in saved search scopes. The URL helper in `frontend/src/readerLocation.ts` is the integration point for future filters; update its parser and serializer alongside the corresponding exported App types.

History keeps at most 30 in-memory snapshots per tab, each with up to 500 loaded articles, 500 detail-sequence entries and 100 selected IDs. Entries with more than 500 loaded articles or detail-sequence entries, or saved while a list is loading, are not cached; returning to one refetches the list rather than restoring a truncated list. Snapshots disappear on reload and are invalidated by reader mutations and list refreshes. A reload, invalidated entry or evicted entry refetches its list and may revisit the linked article. Cursor expiry or changed server data can require a fresh list. Cached restoration reflects captured client state, not a database snapshot, so changes made elsewhere may not appear until refetch. The browser continues to use existing authenticated API and CSRF-protected visits.

Synthetic browser smoke: start the frontend dev server and run `node scripts/reader-history-browser-smoke.mjs` (optionally set `FEEDER_URL`). The script intercepts API requests with synthetic records.
