# 記事詳細・一括操作の検証

2026-11-07。サブエージェントと分担し、画像取得バックエンドと一括操作部品を実装してReactリーダーへ統合した。

記事本文の順序は、取得できた画像（横480px、画面幅以下）・タイトル・秒まで含むJST日時・区切り線・説明・区切り線・前の記事／件数／次の記事。日時不明では明示的な案内を表示する。画像がない場合・取得失敗時は枠を残さない。画像の仕様と通信制限は article-hero-image.md を参照。

外側の主クリック・タッチ・キーボード操作で詳細を閉じ、クリック先の操作は続ける。開く際180ms、閉じる際160msのopacity/translation。閉じ始めた内容は即座にinert・aria-hiddenとし、ポインターを受け付けない。動きの低減ではアニメーションしない。古い通信結果やクリック後の遅延処理が新しい詳細を閉じたり再表示したりしない。

一括操作は選択・実行・選択解除を分離した角丸8pxのテーマ対応プルダウン。選択だけでは更新せず、処理中はロックし、失敗した選択は再試行できる。faviconとヘッダーのSVGは同じ内容であることを実際の配信レスポンスで確認した。

Linuxバックエンド49テストが通過。生成画像fixtureでPC／モバイルの表示順・480px幅・JST日時・favicon一致、選択だけでは未変更・実行・失敗時選択保持、reduced-motionを確認した。通常のブラウザー回帰は画像取得を404へスタブし、実外部サイトへ接続しない。既存の外側操作・遅延visit・記事切替・フォーカス・一覧保持も検証する。実外部サイトごとの画像発見成功は保証しない。
