# Related coverage integration contract

Only v10 calls `story_groups::migrate_catchup(&tx)`. It creates `article_story_index(article_id, canonical_url, body_fingerprint, title_key, published, source_key)` and `article_story_exclusions(article_id)` plus lookup indices. The revision `store_entry` hook updates the index atomically. Existing unobserved articles are not indexed until collected. `related_ids(db: &Connection, article_id: i64, limit: usize) -> rusqlite::Result<RelatedSelection>` returns `members: Vec<RelatedMember { article_id, reason }>`, `total`, `truncated`, `excluded`; reason is `canonical_url` or `content_title_time`. Selection is direct against the anchor, never transitive; excluded anchors and excluded or muted candidates are independent. Candidate scans are capped at 500 per index branch, total counts the evaluated matching set, and truncated reports a cap or response limit. Identical canonical HTTP(S) article URL is sufficient, except a root URL without a meaningful query is never a grouping key; if both titles contain ASCII numbers and those number sequences differ, the pair is rejected even for a matching URL; otherwise exact long normalized body and strong exact normalized title with matching version tokens and publication within 48 hours are required. No original article state is modified.
