# RSS / SNS Reader の残タスク

更新: 2026-11-07。FeederはRust + ReactによるWeb専用の高機能な情報収集ツール／RSS・SNSリーダー。移植元の全機能を再現する計画から、収集・閲覧・整理に必要な機能を選ぶ計画へ変更する。

## 実装済みの基盤

記事の既読・スター・検索・履歴・継続読込、RSS/Atomの発見・プレビュー・購読、定期収集・停止再開・個別間隔、OPML入出力、フォルダー・並べ替え、設定統合、表示設定と設定エクスポート、APIキーとRSS/記事API。機能全体の検証完了を意味せず、詳細は implementation-status.md と各検証記録を参照。

## 優先順位付きの残作業

1. **P0 読書の信頼性:** 継続読込の残る受入、挿入・削除・期限切れ時の復帰、二重既読更新と追加読込失敗を確認。既存の reader-stable-continuation の未完了タスクを閉じる。
2. **P0 運用と保全:** Feeder自身の記事・購読・既読・スター・順序・設定の整合バックアップと復元、更新失敗時の復旧、依存監査、Access認証の実環境受入を記録。画面到達確認と認証境界の検証は区別する。
3. **P1 毎日の読書UI:** URLと戻る／進むによる一覧・詳細・検索の復元を追加。詳細開閉アニメーション・動きの低減・取得可能な画像とJST日時の順序表示は実装済み。次はモバイルのフィード一覧開閉、設定カテゴリの整理、長い名前・大量購読・全テーマの使い勝手。JavaScript無効時の代替経路を仕様化する。
4. **P1 SNS Reader:** 公開Mastodon・Bluesky投稿の購読と通常worker収集を追加。RSS記事と同じ既読・スター・検索・フォルダーで扱う。公開投稿のみ、取得は1回最大40件。提供元の認証不要APIの実接続、ページングによる取りこぼし対策、429の待機最適化は後続。研究ワークスペースなどの依存は設けない。Xの新規収集は対象外。
5. **P1 購読管理と収集状況:** 購読検索・最終確認／エラー表示・最大100件の一括停止／再開・手動再試行は実装済み。次回取得予定・最終成功・連続失敗を区別する収集状態画面を追加。OPML大量取り込み・重複・フォルダー構造の受入を続ける。
6. **P2 APIと設定の持ち運び:** Reader用途のRSS・記事・SNS APIについて互換範囲と意図的差分を確定する。設定JSONの安全なプレビュー付き読み込みを検討し、秘密は取り込まない。旧版の研究APIは互換対象にしない。

## 今回追加したReader機能

1. **共有スマートフォルダー:** DB保存の検索条件。端末別の保存検索は保持し、明示操作で共有へコピー。リビジョン競合を拒否し、消えた購読を全体検索へ広げない。
2. **重複記事:** 最新1,000件の正規化URLでまとめて表示。追跡パラメータのみ除き、元記事・既読・スターを削除・統合しない。
3. **公開SNS:** Mastodon／Blueskyの公開アカウントを購読し、既存workerで収集。非公開・リポスト・Xの新規収集は対象外。
4. **あとで読む:** スターと独立したDB保存。一覧と詳細から保存し、訪問時の自動削除は既定オフ。通常の既読操作では削除しない。
5. **ミュート:** 全体／購読単位のキーワード条件。既定の一覧・一括操作から隠し、条件の無効化や「ミュートした記事も表示」で復帰できる。記事は保持する。
6. **収集診断:** 最終確認、最終成功、次回予定、連続失敗、個別間隔、停止状態。失効した取得リースの結果は記録しない。
7. **URL・履歴復元:** 検索・情報源・記事詳細・一覧位置を戻る／進むで復元。メモリーキャッシュは有限で、再読込ではAPIから復元する。
8. **新着ダイジェスト:** 過去24時間／7日間の実件数を情報源別に集計。外部通知やAI要約は行わない。
9. **Feedly型の1行表示:** 発行元Feed → 記事タイトル → 絶対時刻。購読名を優先し、UTC／JST表示設定を適用する。

検証結果と制限は [今回の統合検証](verification-reader-expansion.md) を参照。

## 次の改善候補

- 共有検索の名称・条件編集UI、共有の整理と順序変更。
- SNSの継続取得・レート制限待機と公式サービスでの実接続受入。
- 大規模ライブラリ向け重複判定の索引化と対象期間指定。
- モバイル用フィード一覧の開閉と、よく使う条件の固定。
- 未読だけの連続閲覧、キーボード操作一覧、選択記事のリンク書き出し。
- 設定JSONの安全な読み込み、依存監査・実環境Access認証の受入。

## 対象外

調査・研究ワークスペース、案件管理、メモ版管理、根拠・引用・添付保全の新機能、entity/relations、出典付き調査レポート、grounded assistant、研究向けwatchlist、network/security/AI研究intelligence、ページ観測と専用rendererを実装計画から除外する。一般のタグや保存検索を追加する場合はReaderの整理機能として別に設計する。

旧FeedAstrolabeデータの移行、旧デスクトップ、Web/local同期、Xの新規収集は引き続き対象外。既存Feederデータの保全要件は維持する。参照スナップショットは過去資料として残し、未移植機能の実装義務とは扱わない。
