# 履歴・詳細検索・一括操作

「最近読んだ記事」は、詳細を開いた最新の順に表示します。詳細閲覧は記事を既読にして履歴を記録します。スター、既読/未読の切替、一括操作、単なるAPI GETでは履歴を増やしません。履歴はライブラリ共通で再起動後も保持し、記事削除とともに消えます。

「詳細検索」で検索対象（タイトル・本文・両方）、並び順、いずれかを含む語句、含まない語句、表示タイムゾーンでの公開日の開始・終了、対象フィードを選び、「条件を適用」します。情報源は複数選択できます。通常検索は一つの文字列として扱い、空白で単語分割しません。

いずれか/除外はカンマ区切りです。語句にカンマがある場合は `"rust, daily",news`、引用符を含む場合はCSVの二重引用符で記述します。グループ同士はAND、いずれかの語句はOR、除外語句はNOTです。各語句256バイトまで、最大20語句、複数フィードは50件までです。無効日付・逆順・無効な情報源・不正なCSVは拒否します。日付絞込みは公開日不明の記事を除きます。日付境界は共有の表示設定（UTC／日本時間）に従います。[表示設定](reader-settings-export.md)を参照してください。

「全て既読」は現在の条件に一致する記事すべてを既読にし、未描画の記事も対象です。検索条件外の記事、スター、履歴は変更しません。

チェックボックスでは最大100件を選択し、選択した記事だけを既読・未読・スター変更できます。追加読込と詳細の往復では選択を保持し、条件変更では解除します。操作により条件から外れた記事は一覧と選択から外れます。サーバーは全IDの存在と条件を検証し、不正なIDが一つでもあれば全部を拒否します。

新しい順・古い順は公開時刻とIDで安定して並べ、公開時刻不明は後ろへ置きます。履歴では最近読んだ順が既定です。ページ番号やユーザー向け表示件数設定は置かず、スクロールで追加します。現段階の内部APIはoffset方式で、同時挿入時のスナップショットや署名付きカーソル互換はまだ提供しません。
