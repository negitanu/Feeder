# Article hero image backend

Article detail (`GET /api/articles/{id}`) and visit (`POST /api/articles/{id}/visit`) include `image_url: string | null`. A non-null value is the relative same-origin `/api/articles/{id}/hero`, and is only a candidate: it does not promise an image. The shared article representation also includes this field in list responses. Render it as an ordinary image using the existing browser session; hide the image on error. The endpoint does not change read, star, or visit state. It returns 404 for absent, invalid, unsafe or unavailable images and 503 when its concurrency limit is reached. Clients should not retry repeatedly. Access follows the existing authentication configuration (including local mode).

On request the backend fetches the stored original URL, never a URL supplied to the endpoint. It reads Open Graph `og:image` first, then `twitter:image`, resolves relative URLs against the final page URL, and fetches through the existing public HTTP(S) address and redirect validation, DNS pinning, no-proxy policy and 2 MiB per-response limit. Both requests together have a 15-second limit. Only JPEG, PNG, GIF and WebP with matching content type and signature are returned, with `nosniff`; SVG is rejected. Up to four loads run concurrently; up to 16 success or failure results are cached in process for five minutes. Responses instruct browsers not to store them. Fetching the page and image reveals the server's IP to those hosts. Existing images or feed metadata are not preserved separately; no schema, migration, or backup behavior changes. There are no background jobs.
