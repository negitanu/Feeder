# Feeder UI / UX polish

2026-11-07。unslop by Damir Sokolovsky ([@heydamir](https://x.com/heydamir)), [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)。手法をFeederの既存ブランドへ適用した。スキル本文の複製は含めていない。

## 監査と方向

判定はpolish。既存の配色、8方向のマーク、画面の機能と順序を保つ。

- 設定画面: 紹介文・フォーム間に大きな空白があり、関連項目のまとまりが弱い。
- 設定・購読管理: 入力、ボタン、ファイル選択で高さ・角丸・文字サイズが異なる。
- 読書画面: READERの大文字ラベルと汎用的な紹介文が見出しを弱めている。
- サイドバー: Unicode記号でサイズ・太さ・ベースラインが異なる。
- 記事一覧: 補助情報が10〜11pxと小さく、複数の文字階層が混在する。
- 記事詳細: 戻る・既読変更・スターの操作部品が揃っていない。
- 検索: 保存検索・詳細検索の枠と主要操作の色が競合する。
- モバイル: 操作部品の高さ、折返し、余白を画面ごとに確認する必要がある。

製品: 多数のRSS・SNS情報源を集め、日々読み進めるリーダー。
性格: 落ち着き、手早さ、明瞭さ。
世界: 見出しを選んで読む、編集室の情報棚。
見せ場: 記事の見出しと選択中の情報源。
固有の印: 既存の8方向マークと意味を持つ未読の点。

## 各パス

1. 余白: 4px基準、デスクトップ操作36px／モバイル40px。設定とカードのグループ間隔を統一。
2. 色: 既存の低彩度背景と緑系ブランドを維持。補助文字を3役に整理し、主要操作以外の色を抑えた。ダークの全件既読を中立色へ修正。
3. アイコン: Lucideの16px・線幅1.5へ統一。ブランドマークは継承。スクリーンリーダーには操作名を維持し装飾SVGを隠す。
4. 文言: READERを削除し、記事の由来を示す短い説明へ変更。検索プレースホルダーを簡潔化。
5. 文字: メタ情報12px（モバイル最小11px）、本文とは別の明確な階層、見出しは主に500。数値は等幅桁。
6. レイアウト: 設定の内容幅960pxを上限として左に揃え、既存の項目順を保持。狭い画面ではフォームを積む。
7. 細部: 共通の角丸、フォーカス、ボタン、ファイル選択、キー表示を整備。長い情報源名の省略とメニュー幅を維持。
8. ビジュアル: 記事タイトルを主役にし、装飾画像や架空の図表を追加しない。生成画像のプロンプトは作成していない。
9. 動き: 背景・文字・枠線の短いフィードバックのみ。reduced-motionと既存の読みやすさ設定を維持。

## 検証

生成データ専用コンテナで修正前・修正後・最終の3回に分けて画像を確認。1440px、390pxと320px、ダーク／ライト／システム、動きの低減、記事詳細を確認した。実データや秘密は画像に使用していない。

型検査・ビルド、読書・詳細・生産性・サイドバー・設定・APIアクセス・保存検索・読みやすさのブラウザー回帰、非root／read-onlyとバックアップ別volume復旧が通過。npm追加時の監査は0件。Lucideはlockfileで固定した。

既存の機能と保存データを維持するpolishであり、SNS収集やURL履歴などの未実装機能を追加した変更ではない。全ブラウザーでの網羅検証は行っていない。
