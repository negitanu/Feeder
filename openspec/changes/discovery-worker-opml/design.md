## Context
The v2 Feeder database stores feeds, folders, article identities, validators and refresh status. Safe fetching pins public addresses, bounds redirects and response size and refuses private destinations.
## Goals / Non-Goals
Goals: bounded discovery and previews, deliberate confirmation, controlled periodic collection, duplicate-aware OPML portability.
Non-goals: external authentication deployment, multi-user isolation, full legacy migration, arbitrary remote XML entities or HTML execution.
## Decisions
Reuse a single public-only fetcher for site/feed/redirect requests; resolve relative alternate links against the final redirect URL and allow at most eight unique feed candidates. Preview returns a safe title, URL and up to five entries. Confirmation uses an unguessable expiring plan bound to an HttpOnly SameSite cookie (15 minutes, bounded in-memory capacity); refetch and revalidate before transaction. Plans do not authorize unrelated writes. Origin/Host checks remain in force.
Add explicit collection settings enabled=false by default and interval_seconds=900 (60..86400). Run `feeder worker` as a separate process; do not implicitly schedule from the Web process. Persist settings and DB-backed per-feed leases so workers/manual refresh cannot overlap, with expiration above the network timeout. Skip paused feeds, check current state before apply and leave data intact on errors. Disable stops new scheduled work; an in-flight bounded fetch may finish. Back up known schema v2 before v3 migration. Keep schema inspection strict for prior recognized schemas.
OPML accepts bounded UTF-8 XML text, rejects DTD/entity declarations and oversized/deep documents, and previews deduplicated URL/folder entries with existing/duplicate/invalid counts. Import is explicit after preview; backend revalidates input and URLs and does not perform outbound network during import. Imported subscriptions are paused until the user resumes them, preserving a deliberate first-fetch boundary. Nested folders flatten into named paths; export reflects current folder membership and preserves pause status using a documented extension. Never import secrets, article bodies or remote OPML URLs.
## Risks / Trade-offs
Preview plans expire or are lost on process restart; users repreview safely. Background operations require a worker process. OPML import preserves valid subscriptions with a visible summary and per-item validation; it does not promise immediate successful collection. Old source specifications remain partially migrated until parity gates are met.
