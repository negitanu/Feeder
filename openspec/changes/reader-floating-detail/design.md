## Design

- Keep the list mounted, visible and its geometry unchanged. Show a right-aligned fixed panel below the visible header and article-area boundary, with independent scrolling, responsive width and theme colors. Recompute bounds on window scroll/resize and article-area resizing; the global header remains interactive.
- Primary pointer/touch actions and keyboard activation outside the panel close it without intercepting the original event; opening another card switches the panel. Escape and the existing close button dismiss it. Explicit close restores focus to the originating card without forcing the page scroll; outside interaction does not steal focus.
- Each detail-opening request receives a monotonically increasing generation. Closing, changing source/filter/page or starting another request invalidates older responses. A successful obsolete visit still reconciles the article's read state and global unread count when the same list scope is active; it never reopens or replaces the chosen detail. Errors from obsolete openings are ignored. A visible loading panel can be closed while the request is pending.
- Preserve selected checkboxes, loaded pages and scroll position, including unread views where a successful visit removes the card. Do not block underlying pointer events. Avoid transition-dependent focus or hidden interactive elements; respect reduced-motion if adding motion.
- Verify generated fixtures with delayed responses, outside clicks, switching cards, focus/keyboard, scrolling, PC/mobile, themes and existing browser regression. No schema change or old data import.
